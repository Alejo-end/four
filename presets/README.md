# demo presets

Five ready-to-play PSETs, so the instrument makes an interesting sound within
a couple of seconds of loading rather than after a minute of dialling. They
live here because `dust/data/` is not part of this repo — reflash the card and
they are gone otherwise.

| # | name | what it shows | material |
|---|------|---------------|----------|
| 1 | CLEAN LOOP | the sample verbatim: PLAY voice, filter open, every effect at zero. The ◇ mark should light. | music box, 115 Em |
| 2 | CHOP PADS | notes routed to slices, SLICE voice, eight of them, delay locked to 1/8 | hiphop break, 97 BPM |
| 3 | GRAIN CLOUD | granular: small grains, dense, wide, pitch-scattered, long tail | atmospheric texture |
| 4 | STRETCH PV | phase vocoder with the scan almost stopped, quarter-note delay | cinematic atmos, Am |
| 5 | EROSION DRIFT | the take ageing as it loops, under shimmer and a nine-second tail | cinematic atmos, Bbm |

Each preset also ships a scene bank of four slots, so SCENE, the morph knob
and ORBIT all do something the moment you load one. Slot 1 is the preset as it
loaded, which makes RCL 1 a reliable way back after you have wandered.

## installing

```sh
rsync -av presets/mangler-0*.pset presets/scenes-0*.lua \
  we@norns.local:~/dust/data/mangler/
```

Then PARAMS > PSET > LOAD on the device.

`mangler.pmap.example` is separate on purpose — copy it to
`~/dust/data/mangler/mangler.pmap` only if you want CC 100 on channel 1 to
work the master STOP. It will overwrite any MIDI mapping you have already
learned.

## what they assume

The `sample_file` path in each preset is absolute and points into
`dust/audio/`, at the Elektron/Octatrack libraries converted to 48 kHz. If
those are not on the card the preset still loads — you get the right settings
over an empty buffer, and the page says EMPTY.

Sample rate matters more than it looks: norns runs at 48 kHz and does not
resample on buffer read, so a 44.1 kHz file plays about 8.8% sharp and every
loop drifts off tempo. The libraries these point at were converted first,
which is also why loading one of these is instant — `load_sample` skips its
conversion path when the rates already agree.

## keeping them honest

These were generated by driving the real script's paramset, so every value was
validated by the same code that runs on the device, and a simulated load
confirmed all 108 params apply with no unknown ids and nothing thrown from a
param action. Two things that check cannot catch:

- They have never been listened to. Balances are reasoned, not heard.
- A preset names parameters by id. Renaming or removing a param leaves a
  silently dead line here, the way `seq_play` outlived the sequencer in the
  MIDI map. If you drop a param, grep this folder for it.

Momentary parameters are all pinned to 0 on purpose. A `1` on `print_take` or
`chaos_throw` would fire its action the instant the preset opened.
